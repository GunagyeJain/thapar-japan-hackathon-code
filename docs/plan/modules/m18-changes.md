## Goal
Every need that arrives after the cutoff (or that the airline's own systems drop) becomes one change event. The router works down a ladder and takes the first rung still physically possible for the time left (caterer list, standby uplift, lounge where allowed, onboard spare, no-show release, never-spoiling reserve pouch, flex swap), tells the passenger honestly, and logs what today's process would have done with the same event. Chaos Mode fires the scripted JL740 events; the metrics compare ThaliBento with today. Screens: `/ops/changes` (Change Control) and `/ops/desk` (Change Desk for check-in, lounge, gate and crew). Spec: `docs/plan/v2.md`.

## Owns
- `backend/app/modules/m18_changes/`, `backend/tests/test_m18_*.py`

## Provides

## Done when
`POST /api/chaos/run` produces the seven events on the right rungs, `/ops/changes` shows them on the ladder with the passenger messages and the today column, and the metrics read from the run.

### Screens (`frontend/src/modules/m18-changes/`)
- **`/ops/changes`, Change control:** header with the current window in words; the cutoff ladder with one dot per event (click to open it); Run Chaos Mode and Reset; the metrics strip (ThaliBento vs today: hard needs, firm needs, meals thrown away, diets known before the cutoff); the change log (time, channel, seat and name, the need as short food rules, window, rung, result, today); the detail panel (the fix in plain words such as "Spare Jain meal · galley 2 · G2-X01", every rung tried, the message in the passenger's language with English below, today's outcome). Below 1700 px the detail sits under the log; on a 1920 projector it sits beside it.
- **`/ops/desk`, Change desk:** counter (Check-in · Lounge · Gate · Crew), find by seat, PNR + surname or surname, the passport card from `/passport/cabin` (tier chips, flex), the need from the passport, m3's `DietPicker` or free text read by `/passport/understand`, kind and an optional note, Submit change → the same decision card, and the last five decisions at this desk. Works at 1024 px (columns stack).
- **`CutoffLadder`** (exported from `@/modules/m18-changes`): `{events?, selectedId?, onSelect?, compact?, className?}`. It reads the flight milestones (`useFlight`) and the sim clock itself, so `/demo` can use it with no props. Time is linear inside each window and every window gets a fixed share of the width (`WINDOW_WEIGHT` in `ladder.ts`), so the 60–90 minute windows near departure stay readable; each window shows its real length.
- **Data:** `api.ts` calls the m18 routes and m17's cabin and understand routes as in `shared/api.md`, polling every 2 s. While a route isn't on the server (FastAPI's 404 "Not Found", or 405 from the page catch-all) it answers from `mock.ts` / `mockDesk.ts` and the header shows a neutral "Sample data" chip; a module's own 404 ("No passenger …") shows as an error. The sample set starts with the seven Chaos Mode events already run (seats and names from the seed; rungs and today outcomes as in v2.md); Reset clears it and Run fires it again.
- **Chaos Mode:** Run posts `/api/chaos/run`, merges the returned events into the log and reveals the new ones 700 ms apart so each lands on its rung while the room watches; the detail panel follows the newest.
- **What the screens read from the backend:** `request.lang` (message language), `request.tiers` (hard or firm need), `decision.item_id` (galley and position come from m6's `/flights/{id}/inventory`, seed items as a fallback), `GET /changes` → `window` for the subtitle. `steps_tried` may be rung ids (each skipped rung then gets a generic reason from `labels.ts`) or `{rung, ok, reason}` objects, whose reasons are shown as sent.
- **Tests:** `ladder.test.ts` (time → x on the ladder, window of a timestamp, dot lanes, span labels), `changes.test.ts` (metrics and tiles, decision wording, desk search and tiers, the stand-in router and reader, when to fall back).
