# ThaliBento v2: the airline keeps listening after the cutoff

Spec for the final build (25 Oct 2026). Every builder reads this file first; `shared/api.md` holds the endpoint rows. Where this file and older module files disagree, this file wins.

## The problem we answer
JAL-PS-01 asks how to serve Indian passengers' diets "throughout their journey", and says the challenge "extends beyond meal pre-booking to include changing or last-minute requirements".

- **The system stops listening at T-25 h.** JAL takes special-meal requests until 25 h before departure (24 h by phone). Three of the brief's four touchpoints (airport, boarding, in-flight) come after that line. After it there is no official channel: "tell the crew".
- **Indian diets are a calendar, not a code.** 81% of Indians limit meat in some way, many only on certain days; 79–85% of Hindus, Jains and Muslims say they fast (Pew 2021). The flight date decides the meal, so many "late" changes can be predicted and asked about before the cutoff.
- **Most passengers never tell us anything.** On JL740, 24 of 186 passengers have a special meal. Everyone else takes chicken or paneer from the trolley, and vegetarians at the back find the paneer gone.
- **The stakes are real.** In 2013 a Delhi consumer commission upheld ₹35,000 against JAL itself for serving non-veg to a couple who booked vegetarian meals.

## The product in one line
ThaliBento keeps listening after the cutoff: it **predicts** diet changes from the calendar and asks before the cutoff, **routes** every late change to the best fix still physically possible at that minute, **loads** a reserve that never goes bad, and helps crew **serve** the right tray at the right time, including when the sun rises at the aircraft.

## Shared shapes
```
Tier      = "hard" | "firm" | "soft"            hard: allergy or religion; firm: medical; soft: taste
TimeRule  = { id, kind: "dates" | "weekday" | "daylight" | "dawn_to_sunset",
              dates?: iso_date[],        kind "dates": the days the rule applies (expanded on the phone)
              weekdays?: int[],          kind "weekday": 0 = Monday … 6 = Sunday
              preset?: "vrat" | "vegetarian",   rules added on those days (m1 presets)
              add_forbid?: tag[],        extra forbids on those days
              after_sunrise_min?: int }  kind "daylight": no food or water from sunset until sunrise + N min
Rules     = { forbid: tag[], allow: tag[], allergens: tag[], tiers: { [tag]: Tier }, flex: boolean, time_rules: TimeRule[] }
Passport  = { id: "PP-…", passenger_id, lang, rules: Rules, code, kitchen_note, label_mark: Text,
              source: "chat" | "form" | "desk" | "ssr" | "seed", confirmed: boolean, updated_at }

Rung      = "ssr_change" | "caterer_add" | "standby_uplift" | "lounge" | "airside_partner" |
            "onboard_spare" | "noshow_release" | "reserve_pouch" | "flex_swap" | "sunrise_box" | "unmet"
Channel   = "chat" | "radar" | "checkin" | "lounge" | "gate" | "crew" | "feed" | "boarding"
ChangeKind= "new_need" | "mind_change" | "lost_request" | "family_member" | "no_show" | "calendar" | "run_out"
ChangeEvent = { id: "CH-…", flight_id, passenger_id | null, seat | null, name | null, at, channel, kind,
                window: Window, request: { forbid, allow, tiers, note, lang },
                decision: { rung: Rung, ok: boolean, item_id | null, spec_id | null, spec_name: Text | null,
                            code | null, kitchen_note | null, reason: Text, steps_tried: Rung[] },
                message: Text | null,          what the passenger is told, in their language first
                today: { ok: boolean, outcome: Text },   what today's process would do with the same event

```

**Privacy (Q&A Q5 stays true).** A passport stores food rules, tiers, dates and weekdays. It never stores the passenger's sentence, a diet name ("Jain", "halal") or the name of a festival or fast. The phone keeps the names for display; the public calendar `shared/rules/calendar.json` lets the server phrase a question ("25 Oct is Sharad Purnima") without storing why the person fasts. Nothing is inferred from a name.

| Window | From → to (JL740) | Rungs, in order |

| `standby_uplift` | → `dispatch_at` (02:05) | `standby_uplift` from the caterer's standby bank, then the onboard rungs |
| `airport` | → `boarding_at` (03:35) | `lounge` (only if enabled for that cabin and hour), `airside_partner` (only if enabled), then the onboard rungs |
| `onboard` | → `std` (04:35) | `onboard_spare`, `noshow_release`, `reserve_pouch`, `flex_swap`, then `sunrise_box` / `unmet` |
| `inflight` | after `std` | same onboard rungs (crew decide, the copilot suggests) |

Airport config lives in m18: DEL lounge (ENCALM, premium cabins only) enabled for cabin C; DEL airside partner disabled 00:00–05:00. The caterer's standby bank for JL740: AVML ×2, VJML ×1, DBML ×1, VGML ×1 (assumption, labelled as such on screen). Every rung only offers what is physically possible: a hard tier is never met by a meal the rules engine calls UNSAFE or NEEDS_HUMAN.

## Seed: who has told us what (m17 seed, deterministic)
- Passengers with an SSR or a cast profile get a passport converted from it (`source: "ssr"`), tiers from their rules (meat, seafood, egg, allium, root vegetables, beef, pork, non-halal meat, allergens → hard; sugar → firm; else soft).
- About half of the remaining passengers answered the T-48 h chat (`source: "chat"`) with a mix based on Pew: non-veg with no beef, vegetarian (lacto), vegetarian no onion-garlic, eggetarian, halal, vegan, no restriction (Japanese and other travellers), diabetic, a few allergies. 30% of "soft" passengers opt into flex.
- Time rules: 29H Meena keeps a fast on 25 Oct (`dates`), 2A Sushila keeps chauvihar (`daylight`, 48 min), two more passengers keep weekday or Purnima fasts.
- Priya (PX-0057) and Mehta (PX-0122) have no passport: Priya creates hers live in Act 1, Mehta asks at the gate.
- The rest have told us nothing: the silent majority that m19 forecasts.

## Story (4 minutes, `/demo`)
1. **Hook (0:20):** `/demo` shows the cutoff ladder: JAL listens once, 25 h before take-off; three of four touchpoints come after. JAL's own ₹35,000 case.
2. **Predict (0:50):** Priya's phone `/jal` (JAL-style site): My Booking 6XK2QP · SHARMA → Special meal → she ticks Vegetarian, Onion & garlic and Purnima fast → Save: AVML + NO ONION NO GARLIC. The Radar sees JL740 is on Sharad Purnima and asks one question on the same page; she taps "Yes"; her meal becomes the fasting version before the cutoff. (25 Oct: the chat step left the story; a form is quicker for passengers.)
3. **Chaos Mode (1:10):** one button fires the seven events; `/ops/changes` shows each on its rung of the ladder with the sim clock moving, each passenger's phone gets the answer, and the "today" column shows what would have happened.
4. **Serve it right (0:50):** crew tablet offline: the serve list, seat colours by tier, 2A's card in Japanese with "eat from 06:xx" (sun at the aircraft), wrong tray red, right tray green; `/ops/load` shows the reserve sized by the newsvendor rule and the universal plate covering 13 of 13 diets.
5. **Proof (0:30):** the metrics panel: hard needs met, meals wasted and diets known before the cutoff, ThaliBento vs today, computed live from the run.

## Rules for every builder
- Never mention Claude, AI, an assistant or an LLM in code comments, docs, UI copy, commit messages or branch names. A language model in the product is "the extraction model" in comments and copy (naming Gemini in identifiers is fine).
- Commit messages `<type>(<module>): <what>`, no trailers. Commit with explicit paths, never `git add -A`.
- New data goes in new module tables (SQLite `create_all` adds new tables but never new columns to old ones). Don't add columns to core tables.
- UI from `@/ui` and the tokens only (`docs/design.md`); EN, HI, JA strings in each module's `i18n.ts`; real seed data; status = icon + word.
- Keep v1 working: the existing story smoke (`e2e/story.spec.ts`) must still pass until m11 replaces it.
